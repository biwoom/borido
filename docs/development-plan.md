## 1. 단계와 진행 방식

기술 설계의 1–8단계에 준비 0단계를 더한 순서를 유지하고 기존 P/W ID를 보존한다. W09는 책임이 다른 W09-A(분류)와 W09-B(트리)로 나눈다. 아래 W09 표기는 두 하위 작업을 포괄한다.

|단계|작업|단계 완료 증거|
|---|---|---|
|0 착수 준비|P00–P02|현재 기준 문서·채택 기록·테스트 정책|
|1 프로젝트 기반|W01–W04|실행·설정·마법사·루트/요청 보호|
|2 콘텐츠 Core|W05–W08|스키마/ID·안전한 저장/CRUD·실효 공개/참조|
|3 경론 분류/트리|W09-A·W09-B·W10|검증 분류·독립 트리·변경/URL 영향/복구|
|4 변환/정적 생성|W11–W16|링크/각주/미디어/인덱스·전체 빌드·원본/출력 보호|
|5 공개 화면|W17–W22|탐색/독서·타 유형·검색/404·반응형/접근성|
|6 편집기 통합|W23–W27|경론 한 편의 편집→저장→미리보기→빌드→독서|
|7 인증/배포|W28–W31|`main` 원본 전송·Actions artifact·승인 대상 실제 확인|
|8 안정화|W32–W34|전체 회귀·복구·새 환경의 전체 흐름|

단계 번호가 검증을 마지막으로 미루라는 뜻은 아니다. 관련 테스트는 각 작업에 포함하고, W32의 로컬 회귀/보안과 W33의 복구 절차를 실제 W31 전송 전에 완료한다. W31 이후 실제 호스팅 결과를 추가 확인한다. 타 유형의 기본 모델은 먼저 정의하되 복잡한 확장은 W27의 경론 흐름 이후 진행한다.

각 작업은 검토 가능한 작은 변경 단위다. 크면 하위 작업으로 나누고 같은 선행 계약/완료 증거를 연결한다. D 참조는 **채택한 규칙**이며 다시 승인받아야 한다는 뜻이 아니다. R 참조는 해당 구현 전 준비할 계약/실증이다. 의존하지 않는 문서/설계 작업은 독립적으로 진행할 수 있다.

## 2. 검증 정책

- U 단위: 상태/ID/정렬/주소/앵커/각주/경로/진단을 오프라인에서 검사.
- I 통합: 격리 임시 프로젝트의 실제 파일 왕복·전체 생성·실패 후 결과/원본 비교.
- B 브라우저: 로컬의 입력/저장·링크/해시·패널/드로어·키보드/초점·뷰포트·JS 비활성.
- S 보안: 루트/심볼릭 링크·Host/Origin/세션·업로드·HTML/프로토콜·비공개 유입·CLI/비밀 비노출.
- M 수동: 실제 경론/출처·글꼴/가독성·OS/기기·인증·승인 호스팅/복구.

완료 보고에는 파일·관련 규칙/작업·명령/환경·성공/실패·미실행 이유·남은 검증을 남긴다. 필수 테스트가 실패하거나 계약/실측이 남으면 해당 작업을 완료로 표시하지 않는다. 문서 검증은 제품 테스트가 아니다.

제품 명령 이름은 `dev`, `validate`, `build`로 유지한다. `dev`는 W03–W04, `validate`는 W05, `build`는 W15–W16의 전체 생성·공개 감사에 연결했다. W01에서 `check`, `test`, `test:e2e`를 환경/패키지 조합과 테스트 러너에 실제 연결했다. 빈 성공 스크립트를 만들어 완료로 처리하지 않는다.

fixture 정책은 다음과 같다.

- 운영 원본 대신 합성 자료와 출처/사용 범위가 확인된 실제 경론의 격리 자료를 사용한다.
- 서로 다른 깊이의 세 트리·개요·빈 구조·긴 제목/한글·한자·음역·긴 표/각주·반복 참조를 포함한다.
- 모든 상태와 조상 조합·잘못된 상태·중복 ID/URL·예약명·없는 분류/본문/문서/앵커/자산·이력 순환/충돌을 포함한다.
- 비공개 제목/경로/본문/전용 자산에 고유 표식을 두어 생성한 HTML/JSON/JS/미디어/리디렉션 등 전체를 검사한다. 이전 공개→비공개 재빌드도 포함한다.
- 공개/비공개 공유 자산·각주/대표 이미지/공통 자산·미등록/미사용 파일을 포함한다.
- 검증 상태 조합을 시험하는 합성 분류는 테스트 프로젝트 안의 가상 자료이며 실제 검증된 분류로 공개하지 않는다.
- 실제 인증/게시 없이 Git/gh 프로세스 대역과 로컬 bare 원격으로 실패/충돌/무전송을 검사한다.
- 성능은 규모·환경·반복 결과와 예산을 R06으로 기록하며 미측정 상태를 통과로 표시하지 않는다.
