## 1. 채택 상태

D01–D22의 추천 방향을 모두 채택했다. **채택은 구현/테스트 통과가 아니다.** 패키지 패치 버전·API 세부 계약·실제 분류/치수·성능·배포 대상은 아래 R 항목에서 검증/보완한다. 이전 검토의 ‘모든 D가 미결정’ 상태를 현재 문서에 반복하지 않는다.

## 2. 과거 요구에서 명시적으로 달라진 부분

|이전 표현/여지|현재 채택과 이유|
|---|---|
|프로그램과 운영 content/config가 한 루트인 예시|프로그램 체크아웃 밖의 사용자 루트. 공개 Git·업데이트 경계를 분리(D02·D18)|
|분류/경론이 모두 `/texts/{slug}/`|분류 `/texts/categories/{slug}/`, 경론 예약명. 충돌 방지(D07)|
|본문 URL의 `{node-path}`|영역 아래 평평한 문서/구조 주소. 같은 영역의 트리 이동에서 주소 유지(D07)|
|구조/본문이 모호한 `_node.json` 예시|영역/구조/본문 유형과 body_file 계약, 개요는 소유 노드에 속함(D04)|
|상위 공개가 하위를 자동 공개하지 않는 규칙만 존재|모든 조상까지 검사하고 숨겨진 공개 자식은 제외 이유 안내(D05)|
|자동 저장/저장 상태 중 선택|명시 저장부터 시작, 충돌·실패·복구를 우선(D06)|
|초기화 후 대시보드·앱 안 프로젝트 이동|경론 목록, 종료 후 수동 이동/새 루트 열기. 복잡한 관리 기능 제외(D02)|
|각주 정의/문서 순서·중첩 지원 혼재|최초 참조 순서·반복 참조 지원·중첩/인라인 제외·정적 하단 기본(D10)|
|미디어 ID 권장·저장 형식 선택|필수 UUID·중앙 목록·명시 공개 상태·필요 자산 선별(D11)|
|도구모음 초기 열거 범위 혼재|필수 탐색과 조건부 원본 연결·인쇄 CSS, 복사/다운로드/크기 조정 후속(D16)|
|URL 이력 중앙/개별 선택|중앙 from→대상 ID, 명시 변경 기록, 빌드는 읽기 전용(D08)|
|일반 설정에서 콘텐츠 스키마 정의 여지|코드 스키마 단일 기준, 설정은 지원된 편집 정책만(D20)|
|여러 문서의 개발 단계/추천 상태 혼재|역할별 현행 문서·단일 P/W 계획·이 결정 기록. 원문은 아카이브(I12)|

이 변경은 사용자가 채택한 추천안의 반영이다. ‘기존 요구를 모두 그대로 유지했다’고 보고하지 않는다. MVP의 핵심은 [M01–M17](product.md#mvp)로 추적하고 변경/조건부 기능을 표시했다.

R 항목은 이미 채택한 아키텍처를 다시 고르는 22개 미결정 목록이 아니다. 승인 범위 안의 구현 계약·측정은 해당 작업에서 구체화하고, 핵심 원칙/범위를 바꿀 필요가 생기면 근거와 영향을 먼저 보고한다. 실제 분류 번호·배포 대상·최종 치수나 성능 수치를 지금 임의로 채워 넣지 않는다.

R01의 W01 범위는 2026-10-29 완료했다. Node 24.22.2/npm 11.14.1, 직접 패키지 8종의 고정 버전/라이선스, 잠금 설치, ESM 조합, macOS 도구 버전과 audit 결과는 [기술 명세 §2.1](technical-spec.md#w01-environment)에 기록했다. Windows/Linux·실제 브라우저와 각 패키지의 제품 계약은 해당 W05·W11·W17 이후 작업에서 계속 검증한다.

## 5. 이번 문서 통합 범위

새 기준 문서와 루트 지침/진입점을 작성하고 기존 기획/명세/로드맵·검토/제안/계획을 [아카이브](archive/README.md)로 보존한다. 기능·코드 스키마·운영 콘텐츠·테스트 코드·패키지·Git·원격 설정·배포는 생성/실행하지 않았다. 문서 검증은 제품 실행 증거를 대신하지 않는다.
