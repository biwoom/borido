# 보리도 프로젝트 작업 지침 — 초안

이 파일은 2026-10-29 문서 검토를 바탕으로 작성한 프로젝트 루트 지침 초안이다. 제품의 미결정 사항을 확정하는 문서가 아니다. 사용자 지시와 승인된 결정이 있으면 그 범위에 맞게 갱신한다.

## 프로젝트 저장소와 최신 검토

- 사용자가 지정한 이 프로젝트의 GitHub 저장소: [biwoom/borido](https://github.com/biwoom/borido).
- Git 원격 주소 형식: `https://github.com/biwoom/borido.git`. 2026-10-29 GitHub 연결로 확인한 공개성은 `public`, 기본 브랜치는 `main`이다. 로컬 폴더는 아직 Git 저장소가 아니며 원격 연결·커밋·푸시를 수행하지 않았다.
- 이 주소를 사용자의 콘텐츠 원본 저장소나 실제 Pages 배포 URL로 자동 대입하지 않는다. 공개 Git 저장소의 파일과 이력은 콘텐츠 `private` 상태로 보호되지 않는다.
- 최신 검토안: [설계 대안 및 문서 통합 제안](<설계 대안 및 문서 통합 제안.md>). D01–D22의 추천안과 문서 재편 계획은 제안 상태이며 채택된 명세가 아니다.
- 최신 사용자 요청은 문서 재편을 위한 우선 검토·대안 제시다. 원문 이동과 통합 명세 재작성은 이 검토 이후의 작업으로 구분한다.

## 현재 작업 범위

- 현재 착수 작업은 문서 검토와 개발 준비다. 저장소 주소 기록·설계 추천안·문서 통합 계획을 포함하며, 기능 구현, 의존성 설치, Git 초기화, 배포를 포함하지 않는다.
- 후속 구현은 사용자가 요청한 범위에서 진행한다. 이미 허용된 작업을 매 단계 다시 승인받을 필요는 없다.
- 현재 로컬 폴더에는 애플리케이션 코드, `package.json`, 테스트 도구와 로컬 Git 저장소가 없다. 아직 존재하지 않는 명령을 실행 가능하다고 보고하지 않는다.

- 구현에 맞춰 원문 명세를 조용히 바꾸지 않는다. 변경 필요성과 근거를 먼저 드러낸다.
- 기존 [개발 로드맵](<개발 로드맵.md>)은 참고 제안이다. 단계 추적에는 작업 ID를 사용한다.

## 아키텍처와 원본 보호

- 콘텐츠 원본은 로컬 Markdown·JSON·미디어 파일이다. 별도 데이터베이스/캐시 서버를 추가하지 않는다.
- `content/`, `media/`, `config/`는 사용자 원본과 설정, `dist/`는 재생성 가능한 공개 결과물이다. 현재는 아직 생성되지 않은 예정 경로다.
- 빌드·미리보기 때문에 원본, ID, 수정 시각을 변경하지 않는다. URL 이력 같은 원본 변경은 승인된 계약에 따른 별도 편집 작업에서 처리한다.
- 앱 업데이트와 프로젝트 초기화를 구분한다. 기존 원본을 무조건 덮어쓰거나, 빌드 실패 시 정상 출력물을 불완전한 결과로 교체하지 않는다.
- `app/admin/`은 UI, `app/server/`는 제한된 로컬 API와 파일/Git 요청, `core/`는 모델·검증·변환·URL·트리, `site/`는 공개 템플릿·스타일·스크립트를 담당한다.
- UI는 서버 API를 통해 파일에 접근한다. Core는 UI에 의존하지 않는다. 템플릿은 정리된 페이지 데이터를 받고 콘텐츠 파일을 직접 탐색하지 않는다.
- ID·제목·파일 경로·slug·공개 URL을 분리한다. 이동·이름 변경 시 ID를 유지한다. 중복 ID/URL을 임의로 재작성해 통과시키지 않는다.
- 경론의 번역·원문·연구 트리를 합치거나 깊이를 고정하지 않는다. 구조와 본문은 최종 승인된 저장 계약(D04)으로 구분한다.
- 테스트용 프로젝트/fixture와 운영 원본을 섞지 않는다. 실제 경론 자동 테스트도 격리된 복제본으로 수행한다.

## 공개 상태와 보안

- 공개 빌드는 `published`만 대상으로 한다. `draft`·`private`의 제목·경로·본문·미디어가 HTML·목록·검색·사이트맵·링크 결과 등 어떤 공개 파일에도 섞이지 않도록 검증한다.
- 상위가 공개라고 하위가 자동 공개되지 않는다. 비공개 조상 아래 공개 자식 정책은 D05 결정 전에 임의 구현하지 않는다.
- 공개 콘텐츠에 실제 필요한 미디어와 공통 필수 자산만 포함한다. `media/` 전체를 자동 복사하지 않는다.
- 서버 기본 바인딩은 `127.0.0.1`이다. 허용 루트 밖 접근, 경로 조작·심볼릭 링크 우회, 악성 업로드를 검증한다.
- 요청 경로를 그대로 파일 경로나 셸 명령으로 사용하지 않는다. Git/CLI 실행은 실행 파일·인자·작업 디렉터리를 분리한다.
- GitHub 비밀번호/PAT를 UI로 받거나 일반 설정·브라우저 코드·콘텐츠·로그에 기록하지 않는다. `gh`를 기본 인증 경로로 쓰되 인증과 쓰기 권한/Pages 설정은 구분한다.
- Markdown/템플릿의 HTML·링크를 검증하고 이스케이프를 유지한다. 정화 허용 목록과 내부 참조 문법은 D09–D10과 함께 확정한다.
- 사용자 원본의 삭제·이동·덮어쓰기에는 기술 §5.4의 영향 확인·검증·사용자 확인·결과 확인·복구 절차를 구현한다. 실제 파일을 다룰 때는 기존 사용자 지시가 허용한 범위를 확인한다.

## UI와 범위 통제

- Basecoat 원본은 수정하지 않는다. 보리도 공통/전용 CSS를 분리하고 필수 기능의 상시 CDN 의존을 피한다.
- 데스크톱 트리는 240px·기본 열림·현재 자료만 표시한다. 오른쪽 목차/각주 패널은 하나를 공유하고 기본 닫힘, 넓은 화면 Push, 좁은 화면 오버레이 가능이다.
- 모바일은 왼쪽 트리/오른쪽 보조 드로어를 동시에 열지 않는다. 아이콘+텍스트 버튼, 각주 없는 문서의 각주 버튼 숨김, 키보드·Escape·초점 복귀를 검증한다.
- 본문 800px, 패널 300px, 줄 간격과 반응형 전환 수치는 시험값이다. 사용자에게 확정 디자인 수치라고 보고하지 않는다.
- 실제 URL 링크, 새로고침·직접 접근·뒤로/앞으로, JS 없는 본문/주요 링크, 경로 접두사·사용자 지정 도메인을 검증한다.
- 초기 제외 기능(계정·협업, 원격 CMS, DB, 지식 그래프, AI 분류, 플러그인 마켓, 자동/예약 배포, 분석·추적 등)을 추가하지 않는다.
- 신수대장경 분류·문헌 소속·번호는 출처를 확인한다. 예시 데이터를 공식 목록으로 취급하지 않는다.

## 작업과 검증 절차

1. 요청 범위, 관련 원문, 작업 ID, 선행 D 항목, 기존 파일/테스트/사용자 변경을 확인한다.
2. 검증 가능한 작은 단위로 변경한다. 관련 없는 재구성·원본 수정·의존성 추가를 섞지 않는다.
3. 영향에 맞는 단위/통합/브라우저/보안 검증을 실행한다. 테스트 실패를 숨기거나 실패 상태에서 무관한 기능을 더하지 않는다.
4. 데이터 구조 변경 시 기존 fixture/콘텐츠 호환성·마이그레이션·복구를 확인한다.
5. 변경 파일, 결과, 실행한 검증, 실행하지 못한 검증과 이유, 남은 결정·다음 작업을 보고한다. 테스트가 없는 상태를 통과로 보고하지 않는다.

### 테스트 명령의 현재 상태

현재 실행 가능한 프로젝트 테스트 명령은 없다. 다음은 기술 §8.1·§12.2의 **예시이며 미구현**이다.

|예시 명령|예정 목적|확정 조건|
|---|---|---|
|`npm run dev`|로컬 편집기 실행|W01에서 실제 스크립트/진입점 확정|
|`npm run validate`|설정·콘텐츠 검증|검증 CLI 구현과 스크립트 연결|
|`npm run build`|정적 사이트 생성|생성기 구현과 스크립트 연결|
|`npm test`|단위·통합 테스트|테스트 도구·fixture·스크립트 도입|
|`npm run test:e2e`|브라우저 흐름 검증|브라우저 도구와 실행 환경 도입|

실제 `package.json`을 작성하면 명령·파일 경로·필요 환경을 이 파일에 갱신하고 실행 결과로 확인한다. 세부 테스트/완료 기준은 [개발 작업 계획](<개발 작업 계획.md>)을 따른다.

## Git과 배포

- 현재 로컬 Git 저장소가 없다는 사실을 유지해서 보고한다. 문서 검토 요청만으로 초기화·커밋·원격 연결을 수행하지 않는다.
- 저장, 빌드, 인증, 원격 연결, 배포는 별도 작업이다. 인증 성공을 배포 승인으로 취급하지 않는다.
- 배포 기능은 빌드·공개 결과/비공개 유입 검사 성공, 저장소·브랜치·변경 결과 확인, 사용자 승인 후 전송하도록 한다(기술 §10.4).
- 실제 원격 전송은 그 대상과 범위에 대한 사용자 허용이 있을 때만 수행한다. 기본 테스트에서는 실제 원격 전송을 하지 않는다.
- 자동 강제 푸시나 확인 없는 원격 이력 재작성은 하지 않는다. 배포 실패 단계와 복구 방법을 표시한다.
- 소스 저장소 공개성·배포 브랜치·도구·`dist/` 추적은 D18 미결정이다. 임의로 `gh-pages` 브랜치나 GitHub Actions를 채택하지 않는다.
