# 보리도 경론 읽기 화면 상세 명세서 v1.0

- 프로젝트: 보리도(Borido)
    
- 대상: 공개 정적 사이트의 경론 읽기 화면
    
- 문서 성격: UI·UX 및 상호작용 상세 명세
    
- 디자인 기반: Basecoat UI
    
- 레이아웃 참조: GitHub 저장소 탐색 인터페이스
    
- 구현 방식: 정적 HTML + CSS + 필요한 JavaScript
    
- 상태: 기본 레이아웃 및 패널 동작 확정, 세부 치수는 구현 검증 후 조정

## 1. 확정된 설계 결정

|항목|확정 사항|
|---|---|
|디자인 기반|Basecoat UI|
|레이아웃 참조|GitHub 저장소의 탐색 및 파일·디렉터리 계층 표시 방식|
|데스크톱 좌측 트리|240px, 기본 열림|
|트리 표시 범위|현재 자료 유형의 트리만 표시|
|데스크톱 오른쪽 패널|기본 숨김|
|데스크톱 패널 열기|본문 영역을 밀어 공간 확보(Push)|
|모바일 좌측 트리|왼쪽에서 열리는 드로어|
|모바일 오른쪽 패널|오른쪽에서 열리는 드로어|
|목차와 각주|동일한 오른쪽 패널에서 전환|
|문서 도구모음|아이콘 + 텍스트 레이블|
|기본 독서 상태|왼쪽 트리 + 중앙 본문, 오른쪽 패널 없음|

### 1.1 설계 원칙

1. 본문을 읽는 행위가 화면의 중심이다.
    
2. 탐색 기능은 항상 접근할 수 있지만, 필요 이상으로 본문을 점유하지 않는다.
    
3. 문서 구조와 자료 유형을 혼동하지 않도록 한다.
    
4. 패널을 열고 닫아도 현재 문서와 읽던 위치가 유지된다.
    
5. 모바일에서는 탐색 기능을 순차적으로 열어 화면 중첩을 방지한다.
    
6. Basecoat의 기본 컴포넌트와 디자인 토큰을 사용하되, 경론 전용 레이아웃은 보리도 고유 컴포넌트로 구현한다.
    
7. 콘텐츠와 URL은 화면 상태와 독립적으로 유지한다.

## 2. 데스크톱 전체 레이아웃

### 2.1 기본 독서 상태

```
┌──────────────────────────────────────────────────────────────────┐
│ 보리도       홈    경론    이야기    블로그    소개         검색  │
├──────────────────────────────────────────────────────────────────┤
│ 홈 / 경론 / 중관부 / 중론 / 번역 / 제1권 / 제2장                  │
├───────────────────┬──────────────────────────────────────────────┤
│                   │                                              │
│ 번역 목차          │  제2장 거래품                                │
│                   │  중론 · 번역 · 제1권                          │
│ ▾ 제1권           │                                              │
│   제1장           │  [☷ 목차] [▤ 각주 3] [자료 전환]              │
│   제2장 ← 현재    │  ──────────────────────────────────────────  │
│   제3장           │                                              │
│ ▸ 제2권           │  본문 제목                                    │
│                   │                                              │
│                   │  본문 문단이 여기에 표시됩니다.               │
│                   │  문단은 편안한 줄 간격과 적절한 폭을 유지합니다.│
│                   │                                              │
│                   │  다음 문단이 이어집니다.                      │
│                   │                                              │
└───────────────────┴──────────────────────────────────────────────┘
```

위 레이아웃은 구조를 설명하는 와이어프레임이다. 최종 UI에서는 Basecoat의 버튼, 테두리, 배경, 글꼴 및 간격 체계를 적용한다.

### 2.2 화면 영역

|영역|초기 너비·규칙|동작|
|---|---|---|
|공통 헤더|전체 너비|사이트 주요 메뉴 제공|
|경로 표시|전체 콘텐츠 너비|상위 분류와 현재 위치 표시|
|왼쪽 트리|240px|현재 자료의 계층 탐색|
|중앙 본문|남은 공간, 본문 최대 너비 적용|문서 제목과 본문 표시|
|오른쪽 보조 패널|기본 숨김|목차·각주 전환|
|푸터|문서 흐름 아래|공통 사이트 정보|

헤더와 경로 표시의 높이는 과도하게 크지 않도록 한다. 본문이 시작되기 전까지 불필요한 세로 공간을 소비하지 않아야 한다.

### 2.3 왼쪽 트리 너비

기본 너비는 **240px**로 한다.

- 데스크톱에서는 트리의 폭을 일정하게 유지한다.
    
- 트리 항목이 길면 적절히 줄바꿈하거나 말줄임 처리한다.
    
- 긴 제목 전체는 필요할 때 브라우저의 기본 툴팁 또는 접근 가능한 보조 설명으로 확인할 수 있다.
    
- 트리 내부는 독립적으로 스크롤할 수 있다.
    
- 화면 높이가 작아도 현재 문서까지 탐색할 수 있어야 한다.
    
- 트리 너비는 중앙 본문이나 오른쪽 패널의 크기에 따라 자동으로 늘어나지 않는다.
    

트리의 너비를 사용자가 조절하는 기능은 v1.0 필수 범위에 포함하지 않는다.

### 2.4 중앙 본문 너비

중앙 본문은 좌측 트리 오른쪽의 가용 공간을 사용하되, 긴 문장의 가독성을 위해 최대 너비를 제한한다.

초기 검토값:

- 본문 최대 너비: 약 800px
    
- 본문 좌우 여백: 약 32~48px
    
- 본문 기본 줄 간격: 글자 크기의 약 1.8~2.0배
    
- 문단 사이 간격: 약 1em 전후
    

이 값은 디자인 토큰의 초기 제안이며 최종 확정값은 아니다. 실제 경론 원문과 한글 번역문, 긴 인용문, 각주가 섞인 문서로 검증한 후 조정한다.

본문은 사용 가능한 공간 안에서 중앙 정렬한다. 화면이 넓다고 본문 글줄이 무한히 길어져서는 안 된다.

## 3. 데스크톱 오른쪽 패널

### 3.1 기본 상태

페이지에 처음 진입하면 오른쪽 패널은 닫혀 있다.

본문 상단 도구모음에는 다음 버튼이 표시된다.

- 목차
    
- 각주 — 해당 문서에 각주가 있을 때만 표시
    

버튼에는 아이콘과 텍스트 레이블을 함께 표시한다. 기능을 아이콘만으로 추측해야 하는 상황을 피한다.

### 3.2 패널 열기: Push 방식

목차 또는 각주 버튼을 누르면 오른쪽 패널이 열리고 중앙 본문 영역이 줄어든다.

```
┌─────────────────────────────────────────────────────────────┐
│ 공통 헤더                                                    │
├───────────────┬────────────────────────────┬────────────────┤
│ 왼쪽 트리     │ 중앙 본문                  │ 오른쪽 패널    │
│ 240px         │ 가용 폭에 맞게 축소        │ 목차 / 각주    │
│               │                            │                │
│               │                            │                │
└───────────────┴────────────────────────────┴────────────────┘
```

동작 규칙:

1. 패널은 오른쪽에서 나타난다.
    
2. 중앙 본문은 패널 너비만큼 줄어든다.
    
3. 왼쪽 트리의 너비는 240px로 유지한다.
    
4. 본문 스크롤 위치는 유지한다.
    
5. 패널이 열려 있는 동안 본문이 지나치게 좁아지면 화면 폭에 따라 대체 동작을 적용한다.
    
6. 패널을 닫으면 본문은 이전 너비로 돌아간다.
    
7. 패널을 열고 닫을 때 현재 문서를 다시 불러오지 않는다.
    

### 3.3 패널 너비

초기 검토값은 약 300px이다.

- 기본 패널 너비: 300px
    
- 긴 각주를 충분히 읽을 수 있는 최소 공간 확보
    
- 패널 내부 콘텐츠는 패널 너비에 맞게 줄바꿈
    
- 패널 내부에서 각주 목록을 독립적으로 스크롤
    
- 패널 상단의 제목과 닫기 버튼은 항상 쉽게 접근 가능
    

각주 내용이 긴 경우 패널 안에서 전체 내용을 읽을 수 있어야 한다. 각주를 단순히 짧은 팝업으로 잘라 표시하지 않는다.

### 3.4 좁은 데스크톱에서의 대응

좌측 트리 240px와 오른쪽 패널 300px를 동시에 표시하면 본문 공간이 부족해질 수 있다.

따라서 다음 규칙을 적용한다.

- 넓은 화면: Push 방식으로 패널 표시
    
- 중간 화면: 패널이 열릴 때 본문 최대 너비 제한을 완화하고 좌우 여백을 줄임
    
- 좁은 화면: 오른쪽 패널을 오버레이로 전환하거나 모바일형 레이아웃 적용
    

정확한 전환 폭은 구현 단계에서 확정한다. 단순히 특정 기기의 이름을 기준으로 나누지 않고, 본문이 읽을 수 있는 최소 너비를 유지할 수 있는지에 따라 결정한다.

## 4. 목차 패널

### 4.1 표시 내용

목차는 현재 본문 문서의 제목 구조를 기반으로 생성한다.

예시:

```
목차                                      [닫기]

1. 서론
2. 본문
   2.1 첫 번째 항목
   2.2 두 번째 항목
3. 결론
```

실제 항목은 문서의 제목과 순서를 그대로 반영한다. 제목이 없는 문단이나 임의로 생성한 항목을 추가하지 않는다.

### 4.2 동작

- 목차 버튼을 누르면 패널이 열리고 목차가 표시된다.
    
- 목차가 이미 열려 있을 때 다시 누르면 패널이 닫힌다.
    
- 각 항목을 누르면 본문의 해당 제목으로 이동한다.
    
- 이동 후 본문 스크롤 위치와 URL 해시가 가능한 한 일관되게 유지된다.
    
- 현재 읽고 있는 위치에 대응하는 목차 항목을 강조할 수 있다.
    
- 현재 위치 강조는 본문을 읽는 데 방해가 되지 않도록 절제된 스타일로 제공한다.
    

### 4.3 목차가 없는 문서

제목 구조가 없어 목차를 만들 수 없다면 목차 버튼과 패널을 표시하지 않거나, 해당 문서에 적합한 최소한의 안내를 제공한다. 불필요한 빈 패널을 노출하지 않는다.

## 5. 각주 패널

### 5.1 표시 내용

각주 패널에는 Markdown 본문에서 정의된 각주를 문서 순서대로 표시한다.

예시:

```
각주                                      [닫기]

[1] 용어 설명
    본문에서 사용한 용어에 관한 설명.

[2] 문헌 참고
    참고 문헌 및 관련 출전.

[3] 번역 참고
    번역상의 선택에 관한 설명.
```

각주 정의는 Markdown 원문에 유지한다. 정적 사이트 빌드 과정에서 각주 참조와 패널 표시용 HTML을 생성한다.

### 5.2 본문과 각주의 연결

1. 본문에 각주 참조 번호를 표시한다.
    
2. 참조 번호를 누르면 각주 패널이 열린다.
    
3. 해당 각주가 패널 안에서 강조된다.
    
4. 패널에서 본문으로 돌아가는 링크를 제공한다.
    
5. 돌아가기를 선택하면 원래 각주 참조 위치로 이동한다.
    
6. 패널을 닫아도 본문 위치는 유지된다.
    

### 5.3 각주가 없는 문서

각주가 하나도 없는 문서에서는 각주 버튼을 표시하지 않는다. 문서 도구모음의 공간은 다른 버튼과 자연스럽게 정렬한다.

### 5.4 긴 각주와 복합 콘텐츠

각주에는 여러 문단, 내부 링크, 외부 링크가 포함될 수 있다. 패널은 긴 내용을 잘라내지 않고 스크롤로 확인할 수 있도록 한다.

각주 내부에 표나 이미지가 존재하는 경우에도 패널 폭을 넘지 않도록 한다. 단, 콘텐츠 원문을 임의로 단순화하거나 의미를 바꾸지 않는다.

## 6. 왼쪽 트리 상세 규칙

### 6.1 트리의 범위

현재 선택한 자료 유형의 트리만 표시한다.

예를 들어 다음 자료가 있다면 각 트리는 독립적으로 구성한다.

- 번역본 트리
    
- 원문 트리
    
- 연구 자료 트리
    

번역본을 읽을 때 원문과 연구 자료의 전체 트리를 왼쪽에 동시에 표시하지 않는다. 다른 자료 유형으로 이동할 수 있는 링크는 문서 제목 영역이나 별도 자료 전환 기능에서 제공한다.

### 6.2 트리 항목

각 항목은 다음 상태를 가질 수 있다.

- 기본
    
- 현재 문서
    
- 펼침
    
- 접힘
    
- 하위 문서가 있는 항목
    
- 이동 가능한 문서
    
- 구조만 있고 본문이 없는 노드
    

현재 문서는 배경색 또는 왼쪽 강조선 등으로 구분한다. 색상만으로 선택 상태를 전달하지 않도록 접근성 상태도 함께 설정한다.

### 6.3 초기 펼침 상태

- 트리는 기본적으로 열려 있다.
    
- 현재 문서가 포함된 상위 노드는 자동으로 펼친다.
    
- 현재 문서의 하위 트리를 모두 무조건 펼칠 필요는 없다.
    
- 불필요하게 깊은 트리는 현재 위치 파악에 필요한 범위에서 표시한다.
    

### 6.4 트리 항목 선택

문서 항목을 선택하면 다음 항목이 갱신된다.

- URL
    
- 경로 표시
    
- 문서 제목
    
- 서지 정보
    
- 본문
    
- 트리의 현재 선택 상태
    
- 해당 문서의 목차와 각주 데이터
    

문서 전환은 전체 페이지 이동으로 구현해도 무방하다. 다만 어느 방식이든 브라우저 뒤로 가기, 앞으로 가기, 새로고침 및 직접 URL 접근이 정상적으로 작동해야 한다.

## 7. 문서 상단 도구모음

### 7.1 기본 구성

도구모음은 문서 제목과 서지 정보 아래, 본문 위에 배치한다.

기본 버튼:

- 목차
    
- 각주 — 각주가 있는 경우
    
- 자료 전환 — 번역·원문·연구 자료 중 다른 자료로 이동할 수 있는 경우
    

자료 전환의 최종 UI는 별도 설계 대상으로 두며, 목차·각주 패널과 혼동하지 않도록 한다.

### 7.2 버튼 표시 방식

- 아이콘과 텍스트 레이블을 함께 표시한다.
    
- 버튼의 클릭 영역은 충분히 확보한다.
    
- 활성 패널과 대응하는 버튼은 선택 상태를 표시한다.
    
- 기능이 없는 버튼은 표시하지 않는다.
    
- 버튼의 접근성 이름과 키보드 조작을 지원한다.
    

### 7.3 패널 상태

패널은 다음 상태를 가진다.

- 닫힘
    
- 목차 열림
    
- 각주 열림
    

같은 버튼을 다시 누르면 패널을 닫는다. 다른 버튼을 누르면 기존 패널을 유지한 채 내용만 전환한다.

## 8. 모바일 레이아웃

### 8.1 기본 독서 상태

모바일에서는 본문을 중심으로 표시한다. 좌측 트리와 오른쪽 패널은 기본적으로 닫혀 있다.

```
┌────────────────────────────┐
│ ☰  보리도             검색 │
├────────────────────────────┤
│ 경론 / 중론 / 번역 / 제1장 │
│                            │
│ 제1장 문서 제목             │
│ 서지 정보                  │
│                            │
│ [자료 트리] [목차] [각주]  │
├────────────────────────────┤
│                            │
│ 본문                       │
│                            │
│ 본문 문단이 화면 너비에     │
│ 맞게 줄바꿈되어 표시됩니다. │
│                            │
└────────────────────────────┘
```

도구모음은 아이콘과 텍스트 레이블을 유지한다. 다만 화면이 매우 좁을 경우 버튼 간격과 패딩을 줄이되, 텍스트를 임의로 제거하지 않는다. 레이블이 모두 들어가지 않는 경우에는 줄바꿈 또는 가로 스크롤 대신 버튼 배치 재조정을 우선 검토한다.

### 8.2 모바일 자료 트리

자료 트리 버튼을 누르면 왼쪽에서 드로어가 열린다.

동작 규칙:

- 트리 드로어는 현재 자료의 트리만 표시한다.
    
- 현재 문서를 강조한다.
    
- 항목을 선택하면 해당 문서로 이동하고 드로어를 닫는다.
    
- 닫기 버튼과 바깥 영역 선택으로 닫을 수 있다.
    
- 키보드 초점은 드로어 내부로 이동하고, 닫을 때 적절히 복귀한다.
    
- 트리가 열려 있는 동안 본문은 배경 영역으로 유지한다.
    

### 8.3 모바일 목차·각주 패널

목차 또는 각주 버튼을 누르면 오른쪽에서 드로어가 열린다.

- 목차와 각주는 같은 패널을 공유한다.
    
- 패널 상단에는 제목, 전환 버튼, 닫기 버튼을 표시한다.
    
- 긴 목차와 각주 내용은 패널 내부에서 스크롤한다.
    
- 각주 참조를 선택하면 해당 각주가 강조된다.
    
- 본문으로 돌아갈 때 읽던 위치를 유지한다.
    

### 8.4 드로어 중복 방지

모바일에서는 좌측 트리와 오른쪽 패널을 동시에 열지 않는다.

- 트리가 열려 있을 때 목차·각주를 열면 트리를 닫고 보조 패널을 연다.
    
- 보조 패널이 열려 있을 때 트리를 열면 보조 패널을 닫고 트리를 연다.
    
- 드로어가 닫혀 있을 때는 본문 전체를 읽을 수 있다.
    

이 규칙은 모바일 화면에서 두 개의 패널이 중첩되거나 본문이 불필요하게 가려지는 문제를 방지한다.

## 9. 반응형 전환 규칙

정확한 브레이크포인트는 실제 화면 테스트 후 확정한다. 다음은 초기 구현 기준이다.

|화면 범위|레이아웃|
|---|---|
|넓은 데스크톱|좌측 트리 240px + 중앙 본문, 패널은 Push|
|중간 데스크톱|좌측 트리 240px 유지, 본문 여백 조정, 필요 시 패널 오버레이|
|태블릿|트리 표시 여부를 공간에 따라 조정, 보조 패널은 필요 시 오버레이|
|모바일|본문 중심, 트리와 보조 패널은 각각 드로어|

초기 테스트용 브레이크포인트는 다음과 같이 둘 수 있다.

- 1200px 이상: 넓은 데스크톱
    
- 900~1199px: 중간 화면
    
- 899px 이하: 축소된 탐색 레이아웃 검토
    
- 640px 이하: 모바일 중심 레이아웃
    

이 수치는 잠정값이다. 좌측 트리와 본문이 실제로 자연스럽게 공존하는지 확인한 뒤 조정한다.

## 10. 스크롤 및 초점 관리

### 10.1 스크롤

- 본문은 페이지의 주 스크롤 영역으로 유지한다.
    
- 좌측 트리는 자체 스크롤을 허용한다.
    
- 오른쪽 패널은 패널 내부에서 긴 내용을 스크롤할 수 있다.
    
- 패널을 열고 닫을 때 본문 스크롤 위치를 초기화하지 않는다.
    
- 목차 항목을 누르면 해당 제목으로 이동한다.
    
- 각주 참조를 누르면 해당 각주가 패널 안에서 보이도록 이동한다.
    

### 10.2 초점

- 드로어가 열리면 초점을 해당 영역으로 이동한다.
    
- 드로어가 닫히면 초점을 드로어를 열었던 버튼으로 돌려준다.
    
- Escape 키로 열린 패널을 닫을 수 있도록 한다.
    
- 키보드로 트리 항목과 도구모음을 탐색할 수 있어야 한다.
    
- 패널 전환 후에도 현재 선택 상태를 접근성 속성으로 전달한다.

## 11. URL과 상태 관리

### 11.1 문서 URL

문서마다 안정적인 URL을 가진다. 자료 유형과 트리 경로는 URL 구조와 콘텐츠 데이터 명세서에 정의된 규칙을 따른다.

### 11.2 패널 상태

목차·각주 패널의 열림 상태는 기본적으로 일시적인 UI 상태로 취급한다.

- 문서 진입 시 패널은 닫힌다.
    
- 패널 열기·닫기는 본문 문서 URL을 변경하지 않는다.
    
- 목차 이동은 필요할 경우 URL 해시를 갱신한다.
    
- 각주 참조와 본문 위치 이동은 안정적인 앵커를 사용한다.
    
- 브라우저 뒤로 가기는 문서 간 이동에 대해 정상적으로 동작해야 한다.
    

패널 상태를 URL에 포함하는 기능은 v1.0 필수 범위에 넣지 않는다.

## 12. Basecoat UI와 커스텀 컴포넌트

### 12.1 Basecoat 활용

가능한 경우 Basecoat의 버튼, 탭, 사이드바, 기본 상호작용 패턴을 사용한다.

### 12.2 보리도 전용 컴포넌트

다음은 보리도 전용 CSS와 JavaScript로 구현한다.

- 경론 트리 항목과 계층 표시
    
- 문서 상단 도구모음
    
- 독서 레이아웃
    
- 목차·각주 통합 패널
    
- 본문 각주 참조와 패널 사이의 이동
    
- 문서 제목 및 서지 정보 영역
    

Basecoat 기본 컴포넌트를 직접 수정하지 않고, 보리도 전용 클래스와 CSS 변수를 이용해 시각적으로 통일한다.

### 12.3 구현 시 주의

- 같은 기능을 여러 방식으로 중복 구현하지 않는다.
    
- 필요하지 않은 UI 라이브러리나 JavaScript 의존성을 추가하지 않는다.
    
- 정적 HTML만으로도 본문과 주요 링크에 접근할 수 있도록 한다.
    
- 키보드, 모바일 터치, 브라우저 기본 동작을 모두 고려한다.

## 13. 구현 검증 체크리스트

### 데스크톱

- 왼쪽 트리가 240px로 표시된다.
    
- 트리가 기본적으로 열려 있다.
    
- 현재 자료 유형의 트리만 표시된다.
    
- 오른쪽 패널이 기본적으로 숨겨져 있다.
    
- 목차 버튼을 누르면 패널이 열린다.
    
- 각주 버튼을 누르면 같은 패널에서 각주가 열린다.
    
- 패널이 열리면 넓은 화면에서 본문이 밀려난다.
    
- 좁은 화면에서는 본문 폭이 과도하게 줄어들지 않는다.
    
- 패널을 닫아도 읽던 위치가 유지된다.
    
- 각주 참조와 각주 내용 사이를 이동할 수 있다.
    

### 모바일

- 본문이 기본 화면이다.
    
- 자료 트리는 왼쪽 드로어로 열린다.
    
- 목차·각주 패널은 오른쪽 드로어로 열린다.
    
- 두 드로어가 동시에 열리지 않는다.
    
- 드로어를 닫아도 본문 위치가 유지된다.
    
- 긴 각주를 패널 내부에서 읽을 수 있다.
    
- 버튼과 링크가 터치하기 충분한 크기를 가진다.
    
- 화면 가로 넘침이 발생하지 않는다.
    

### 공통

- 본문 제목, 서지 정보, 트리, 목차가 올바른 문서와 연결된다.
    
- 새로고침과 직접 URL 접근이 정상 작동한다.
    
- 브라우저 뒤로 가기와 앞으로 가기가 정상 작동한다.
    
- 키보드로 메뉴와 패널을 조작할 수 있다.
    
- Basecoat 기본 스타일과 보리도 커스텀 스타일이 일관성을 유지한다.
    
- CDN이 없어도 사이트의 필수 기능이 작동한다.

## 14. 후속 확정 사항

이 명세서에서 레이아웃 방향과 상호작용은 확정한다. 구현에 앞서 다음 항목은 실제 콘텐츠를 넣은 화면으로 검증한다.

1. 좌측 트리 240px가 긴 경론 제목에서도 적절한지
    
2. 본문 최대 너비와 줄 간격이 한글·한자 혼합 문서에 적합한지
    
3. 오른쪽 패널 너비 300px가 긴 각주를 읽기에 충분한지
    
4. Push에서 오버레이로 전환하는 정확한 화면 폭
    
5. Basecoat 스타일 팩과 색상 변수
    
6. 모바일 드로어의 너비와 애니메이션
    
7. 목차의 현재 위치 강조 방식
    

이 항목들은 기존 레이아웃 결정을 바꾸기 위한 것이 아니라, 구현 품질을 높이기 위한 검증 항목이다.

## 15. 최종 요약

보리도 경론 읽기 화면은 GitHub 저장소의 탐색 구조를 참조하면서, 본문을 읽는 경험을 중심에 둔다.

데스크톱에서는 왼쪽에 240px 트리를 기본으로 열어 두고, 중앙에 본문을 표시한다. 오른쪽 목차·각주 패널은 기본적으로 숨겨 두며, 문서 도구모음에서 호출한다. 패널이 열리면 넓은 화면에서는 본문을 밀어 공간을 확보하고, 공간이 부족한 화면에서는 오버레이 방식으로 전환한다.

모바일에서는 본문을 기본 화면으로 유지한다. 자료 트리는 왼쪽 드로어로, 목차·각주 패널은 오른쪽 드로어로 제공하며 두 패널은 동시에 열리지 않는다.

Basecoat UI의 공통 컴포넌트를 활용하고, 경론 트리와 독서 화면의 고유 기능은 보리도 전용 컴포넌트로 구현한다. 콘텐츠와 UI를 분리하고, URL과 브라우저 기본 탐색이 안정적으로 작동하도록 한다.

**핵심 목표는 경론의 구조를 쉽게 찾으면서도, 읽는 동안에는 인터페이스가 뒤로 물러나 본문에 집중할 수 있는 화면을 만드는 것이다.**
