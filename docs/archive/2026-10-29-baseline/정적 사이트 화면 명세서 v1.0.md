# 보리도(Borido) 정적 사이트 화면 명세서 v1.0

- 문서 유형: 화면 구조 및 사용자 경험 명세서
    
- 대상: 보리도 공개 정적 사이트
    
- 상태: 설계 기준 확정 및 세부 화면 설계 초안
    
- 디자인 기반: Basecoat UI
    
- 레이아웃 참조: GitHub 저장소 및 파일 탐색 인터페이스
    
- 콘텐츠 유형: 경론, 이야기, 블로그, 일반 페이지
    

---

## 1. 목적과 설계 원칙

### 1.1 목적

보리도 정적 사이트는 경론과 불교 콘텐츠를 안정적으로 탐색하고 읽을 수 있는 공개 웹사이트다. 본 문서는 전체 화면 구조, 공통 인터페이스, 콘텐츠 유형별 페이지, 반응형 동작 및 화면 상태를 정의한다.

이 명세서는 로컬 콘텐츠 관리 도구나 콘텐츠 데이터 구조를 재정의하지 않는다. 콘텐츠 데이터 및 파일 구조 명세서에서 정의한 콘텐츠를 공개 사이트에서 어떻게 표시하고 탐색할 것인지를 다룬다.

### 1.2 확정된 설계 기준

1. **Basecoat UI를 기본 디자인 기반으로 사용한다.**
    
2. GitHub 저장소의 탐색 구조, 계층 표시, 현재 위치 강조, 파일 탐색 방식을 참조한다.
    
3. 기본 레이아웃은 공통 헤더와 콘텐츠 영역으로 구성하며, 경론 읽기 화면에서는 좌측 트리와 중앙 본문을 중심으로 구성한다.
    
4. 경론 읽기 화면의 왼쪽 트리에는 현재 자료에 해당하는 트리만 표시한다.
    
5. 오른쪽 보조 패널은 기본적으로 숨긴다. 본문 상단 도구모음에서 목차 또는 각주 기능을 선택하면 패널이 열린다.
    
6. 목차와 각주는 동일한 오른쪽 패널을 공유하며, 두 기능 사이를 전환할 수 있다.
    
7. 모바일에서는 GitHub의 저장소 탐색 방식처럼 탐색 영역을 필요할 때 열고 닫을 수 있도록 한다.
    
8. 콘텐츠와 표현을 분리한다. Basecoat의 기본 스타일을 활용하되, 보리도 고유 CSS는 별도 계층으로 유지한다.
    
9. 공개 사이트는 정적 파일로 생성하며, 페이지 이동은 실제 URL을 기반으로 한다.
    
10. 콘텐츠가 없는 기능이나 사용하지 않는 패널을 불필요하게 표시하지 않는다.
    

### 1.3 핵심 사용자 경험

보리도의 화면은 다음 세 가지를 우선한다.

- **발견:** 분류와 계층을 통해 원하는 콘텐츠를 찾는다.
    
- **이해:** 현재 문서의 위치와 전체 구조를 파악한다.
    
- **독서:** 탐색 기능이 본문 읽기를 방해하지 않도록 한다.
    

시각적인 장식보다 콘텐츠 구조의 명료성, 긴 글의 가독성, 안정적인 탐색을 우선한다.

## 2. 디자인 시스템

### 2.1 Basecoat UI 적용 원칙

Basecoat UI는 기본 컴포넌트와 스타일을 제공하는 디자인 기반으로 사용한다. 모든 화면을 Basecoat 기본 모양 그대로 구성하는 것은 아니며, 보리도에 필요한 레이아웃과 콘텐츠 표현을 추가한다.

공식 문서:

- Basecoat UI: [https://basecoatui.com/](https://basecoatui.com/)
    
- 설치 및 스타일 구성: [https://basecoatui.com/installation/](https://basecoatui.com/installation/)
    
- Sidebar: [https://basecoatui.com/components/sidebar/](https://basecoatui.com/components/sidebar/)
    
- Tabs: [https://basecoatui.com/components/tabs/](https://basecoatui.com/components/tabs/)
    

적용 범위는 다음과 같다.

|영역|적용 방식|
|---|---|
|버튼, 링크, 입력 요소|Basecoat 기본 스타일 활용|
|메뉴와 드롭다운|필요한 경우 Basecoat 컴포넌트 활용|
|모바일 탐색 드로어|Basecoat Sidebar 또는 적합한 기본 구조 활용|
|목차·각주 전환|Basecoat Tabs의 접근성 패턴 활용|
|대화상자|필요한 경우 네이티브 dialog 및 Basecoat 스타일 활용|
|본문 타이포그래피|보리도 전용 CSS로 조정|
|경론 트리|Basecoat 스타일을 바탕으로 보리도 전용 컴포넌트 구현|
|문서 읽기 레이아웃|보리도 전용 CSS|
|각주 패널|Basecoat 패널·탭 스타일을 활용한 전용 컴포넌트|
|콘텐츠 카드와 목록|Basecoat의 간격·테두리·색상 체계를 활용해 구현|

### 2.2 CSS 계층

스타일은 세 계층으로 관리한다.

1. **Basecoat 기본 계층:** 기본 컴포넌트 및 스타일 팩
    
2. **Borido 공통 계층:** 색상 변수, 글꼴, 간격, 콘텐츠 너비, 반응형 규칙
    
3. **Borido 컴포넌트 계층:** 경론 트리, 독서 레이아웃, 문서 도구모음, 각주 패널 등
    

Basecoat의 기본 파일을 직접 수정하지 않는다. 커스텀 스타일은 별도 파일에 두어 향후 Basecoat 버전 변경이나 교체의 영향을 줄인다.

### 2.3 스타일 팩

Basecoat에서 제공하는 스타일 팩 중 하나를 기본값으로 선택한다. 스타일 팩 선택은 버튼, 패널, 테두리, 배경 등 공통 컴포넌트의 시각적 일관성을 확보하기 위한 결정이다.

최종 스타일 팩은 실제 경론 읽기 화면을 기준으로 확인한 뒤 확정한다. 여러 스타일 팩을 페이지마다 혼용하지 않는다.

### 2.4 시각적 원칙

- 밝고 차분한 문서 중심의 인터페이스를 기본으로 한다.
    
- 배경, 테두리, 글자 색상은 명확한 계층을 형성하되 과도한 대비나 장식을 피한다.
    
- 카드와 패널은 기능적으로 구분할 필요가 있을 때만 사용한다.
    
- 아이콘은 기능을 보조하며, 아이콘만으로 중요한 기능을 설명하지 않는다.
    
- 선택된 메뉴와 현재 문서의 위치를 명확하게 표시한다.
    
- 본문은 장시간 읽기 편한 너비와 줄 간격을 유지한다.
    
- 이미지와 장식 요소가 텍스트의 가독성을 해치지 않도록 한다.
    

### 2.5 타이포그래피

본문과 인터페이스의 글꼴 규칙을 분리한다.

- 인터페이스: 한글과 영문이 자연스럽게 혼합되는 읽기 쉬운 글꼴
    
- 본문: 한글 장문 읽기에 적합한 글꼴과 줄 간격
    
- 한자·팔리어·산스크리트어: 해당 문자가 올바르게 표시되는 대체 글꼴 구성
    
- 인용문·각주·서지 정보: 본문과 구분하되 과도하게 축소하지 않음
    

본문의 기본 너비, 본문 글자 크기, 줄 간격은 실제 경론 자료를 이용한 시안에서 검증한다. 한글과 한자가 혼합된 문헌에서 글꼴 대체가 일어나더라도 줄 높이가 불규칙하게 변하지 않아야 한다.

## 3. 공통 사이트 레이아웃

### 3.1 전체 구조

공개 사이트의 기본 구조는 다음과 같다.

```
┌─────────────────────────────────────────────┐
│ 헤더: 로고 · 홈 · 경론 · 이야기 · 블로그 · 소개 │
├─────────────────────────────────────────────┤
│ 페이지 제목 / 경로 표시 / 선택적 도구          │
├─────────────────────────────────────────────┤
│                                             │
│                페이지 콘텐츠                 │
│                                             │
├─────────────────────────────────────────────┤
│ 푸터: 소개 · 라이선스 · 관련 정보             │
└─────────────────────────────────────────────┘
```

경론 읽기 화면은 공통 헤더 아래에 별도의 문서 탐색 레이아웃을 적용한다.

### 3.2 헤더

헤더는 사이트 전역에서 동일한 기본 구조를 유지한다.

구성 요소:

- 보리도 로고 또는 사이트 이름
    
- 홈
    
- 경론
    
- 이야기
    
- 블로그
    
- 소개
    
- 검색 진입점
    

동작 규칙:

- 로고 또는 사이트 이름을 누르면 홈으로 이동한다.
    
- 현재 주요 메뉴는 시각적으로 구분하고 `aria-current="page"` 등 적절한 접근성 표시를 제공한다.
    
- 모바일에서는 공간이 부족할 경우 메뉴를 접어 탐색 버튼으로 전환한다.
    
- 경론 읽기 화면에서도 헤더를 유지하되, 본문 공간을 지나치게 줄이지 않는다.
    

### 3.3 경로 표시(Breadcrumbs)

현재 위치를 상위 콘텐츠와 연결한다.

예시:

```
홈 / 경론 / 중관부 / 문헌 제목 / 번역 / 제1장
```

규칙:

- 실제 상위 경로가 존재하는 항목만 표시한다.
    
- 이동 가능한 상위 항목은 링크로 제공한다.
    
- 현재 위치는 링크와 시각적으로 구분한다.
    
- 경로가 길면 작은 화면에서 중간 항목을 축약할 수 있다.
    
- 경로 표시는 탐색 트리를 대체하지 않는다.
    

### 3.4 푸터

푸터에는 사이트 소개, 라이선스, 저작권 및 필요한 공개 정보를 표시한다.

콘텐츠별 추가 정보가 있다면 해당 콘텐츠의 본문이나 서지 영역에 표시한다. 푸터는 독서에 방해가 되지 않도록 간결하게 유지한다.

## 4. 경론 읽기 화면

### 4.1 목적

경론 읽기 화면은 보리도에서 가장 중요한 화면이다. 경론의 계층 구조를 탐색하면서 본문을 읽고, 필요할 때 목차와 각주를 확인할 수 있어야 한다.

### 4.2 기본 레이아웃

```
┌────────────────────────────────────────────────────┐
│ 공통 헤더                                           │
├────────────────────────────────────────────────────┤
│ 경로 표시                                           │
├──────────────┬─────────────────────────────────────┤
│              │ 문서 제목                            │
│ 왼쪽 자료 트리 │ 서지 정보                            │
│              │ 문서 도구모음                         │
│ 현재 자료의   ├─────────────────────────────────────┤
│ 하위 구조만   │                                     │
│ 표시          │ 본문                                │
│              │                                     │
│              │                                     │
│              │                                     │
└──────────────┴─────────────────────────────────────┘
```

기본 상태에서는 오른쪽 패널을 표시하지 않는다. 본문은 사용 가능한 가로 공간을 최대한 활용하되, 지나치게 넓어져 장문 읽기가 어려워지지 않도록 본문 최대 너비를 설정한다.

### 4.3 왼쪽 트리

왼쪽 트리는 현재 열어 본 자료에 속하는 트리만 표시한다.

예를 들어 현재 자료가 번역본이라면 번역본의 권·장·절 등 해당 자료의 계층만 표시한다. 원문이나 연구 자료의 트리를 같은 영역에 함께 표시하지 않는다.

구성:

- 트리 제목 또는 자료 유형
    
- 계층 항목
    
- 펼치기·접기 컨트롤
    
- 현재 문서 강조
    
- 트리 영역 내부 스크롤
    

동작 규칙:

- 항목 제목을 누르면 해당 문서 또는 노드로 이동한다.
    
- 하위 항목이 있는 경우 펼치기·접기 기능을 제공한다.
    
- 현재 문서는 명확한 활성 상태로 표시한다.
    
- 현재 문서의 상위 경로는 필요에 따라 자동으로 펼쳐 표시한다.
    
- 트리에서 다른 문서로 이동하면 URL과 본문이 함께 변경된다.
    
- 트리의 접기 상태가 URL이나 문서 접근을 방해하지 않아야 한다.
    
- 트리에 구조 노드와 본문 문서가 모두 존재하는 경우 시각적으로 구분한다.
    

트리는 콘텐츠 데이터의 계층 구조를 표현하며, 화면에서 보이는 깊이를 임의로 제한하지 않는다. 깊이가 깊은 경우 들여쓰기를 무한히 늘리기보다 선·간격·아이콘 등을 활용해 계층을 식별한다.

### 4.4 본문 제목과 서지 정보

본문 상단에는 현재 문서 제목과 필요한 서지 정보를 표시한다.

표시할 수 있는 정보:

- 문서 제목
    
- 원전 또는 상위 경론 제목
    
- 번역자 또는 저자
    
- 권·장·절 정보
    
- 판본이나 출전 정보
    
- 선택적인 설명
    

모든 정보를 항상 표시하지 않는다. 자료에 존재하고 독자에게 필요한 정보만 노출한다.

### 4.5 문서 도구모음

도구모음은 문서 제목과 본문 사이에 배치한다.

필수 기능:

- 목차 열기
    
- 각주 열기 — 각주가 있는 경우에만 제공
    

필요에 따라 이후 추가할 수 있는 기능:

- 원문·번역·연구 자료로 이동
    
- 문서 링크 복사
    
- 인쇄
    
- 글자 크기 조정
    

이후 기능은 v1.0의 필수 범위가 아니다.

도구모음 규칙:

- 버튼은 기능을 명확하게 설명하는 텍스트 또는 접근성 이름을 가진다.
    
- 목차와 각주 버튼은 현재 패널 상태를 알 수 있도록 표시한다.
    
- 패널이 열려 있을 때 같은 버튼을 누르면 패널을 닫을 수 있다.
    
- 다른 패널 기능을 누르면 패널을 유지한 채 내용을 전환한다.
    
- 각주가 없는 문서에서는 각주 버튼을 표시하지 않는다.
    
- 목차를 생성할 수 있는 제목이 없는 경우 빈 목차 패널을 억지로 제공하지 않는다.
    

### 4.6 오른쪽 보조 패널

오른쪽 패널은 기본적으로 숨긴 상태로 시작한다.

패널이 열리면 중앙 본문과 좌측 트리 사이 또는 오른쪽 가장자리에서 독립된 보조 영역으로 표시한다. 데스크톱에서는 가능한 한 본문을 밀어내는 방식으로 구성하되, 가로 공간이 부족한 화면에서는 오버레이 방식으로 전환할 수 있다.

패널 상단 구성:

- 현재 패널 제목
    
- 목차 또는 각주 전환 버튼
    
- 닫기 버튼
    

#### 목차 모드

- 현재 문서의 제목 구조를 기반으로 생성한다.
    
- 제목 계층을 들여쓰기 등으로 구분한다.
    
- 항목을 누르면 본문의 해당 위치로 이동한다.
    
- 현재 읽고 있는 위치에 대응하는 항목을 시각적으로 강조할 수 있다.
    
- 본문에 존재하지 않는 제목을 임의로 생성하지 않는다.
    

#### 각주 모드

- Markdown 원문에 정의된 각주를 표시한다.
    
- 각주 번호와 본문 참조 번호를 연결한다.
    
- 각주 참조를 누르면 패널이 열리고 해당 각주가 강조된다.
    
- 각주 패널에서 각주 번호 또는 돌아가기 컨트롤을 누르면 본문의 참조 위치로 돌아갈 수 있다.
    
- 각주가 여러 개일 경우 문서에서 정의된 순서를 유지한다.
    
- 각주 내용에 다른 각주나 내부 링크가 포함될 경우 해당 링크도 정상적으로 작동해야 한다.
    

#### 패널 공통 규칙

- 패널이 열려 있는 동안 본문 읽기 위치가 불필요하게 초기화되지 않는다.
    
- 패널을 닫아도 현재 본문 위치가 유지된다.
    
- URL을 통한 직접 접근과 새로고침이 정상적으로 작동한다.
    
- 패널의 열림 상태는 문서의 핵심 콘텐츠 접근을 위한 필수 조건이 아니다.
    
- 패널이 열렸을 때 본문 너비가 너무 좁아지면 오버레이 또는 패널 너비 조정으로 대응한다.
    

### 4.7 본문 표현

본문은 Markdown 콘텐츠를 읽기 적합한 HTML로 변환해 표시한다.

지원해야 하는 주요 요소:

- 제목과 문단
    
- 순서 있는 목록과 순서 없는 목록
    
- 인용문
    
- 표
    
- 이미지
    
- 내부 링크와 외부 링크
    
- 각주
    
- 코드 또는 특수 서식이 필요한 텍스트
    

경론 콘텐츠에서 중요한 한자, 산스크리트어, 팔리어, 음역어가 손상되지 않아야 한다. 인용문, 원문, 번역문은 필요할 때 시각적으로 구분할 수 있지만, 콘텐츠의 의미나 구조를 임의로 변경하지 않는다.

## 5. 경론 분류 및 목록 화면

### 5.1 경론 대분류 화면

경론 메뉴의 첫 화면은 설정된 대장경 분류 체계의 주요 분류를 보여준다.

구성:

- 페이지 제목과 간단한 설명
    
- 대분류 목록
    
- 각 분류의 이름
    
- 선택적인 설명
    
- 선택적인 수록 문헌 수
    

분류를 선택하면 해당 분류의 경론 목록으로 이동한다.

분류 이름과 분류 순서는 별도 설정 데이터에서 가져온다. 화면 코드에 분류 목록을 직접 고정하지 않는다. 실제 분류 명칭과 문헌 배속은 권위 있는 목록을 대조해 확정해야 한다.

### 5.2 분류별 경론 목록

구성:

- 경로 표시
    
- 분류 제목과 설명
    
- 해당 분류의 경론 목록
    
- 문헌 제목
    
- 선택적인 저자·번역자·서지 정보
    

목록은 문헌을 쉽게 찾을 수 있도록 제목을 중심으로 구성한다. 목록에 표시할 부가 정보는 데이터가 존재하는 경우에만 나타낸다.

문헌이 많아질 경우 정렬 또는 페이지 분할을 도입할 수 있다. v1.0에서는 대규모 목록에 대한 고급 필터를 필수 기능으로 두지 않는다.

### 5.3 경론 상세 진입

개별 문헌을 선택하면 해당 문헌의 기본 화면 또는 기본 자료로 이동한다.

문헌에 번역·원문·연구 자료가 존재한다면 독자가 자료 간 관계를 파악할 수 있는 진입점을 제공한다. 자료 유형별 트리는 각각 독립적으로 표시한다.

## 6. 홈 화면

홈 화면은 사이트의 목적과 콘텐츠 영역을 간결하게 안내한다.

구성:

- 보리도 이름과 짧은 소개
    
- 경론으로 이동하는 주요 진입점
    
- 이야기로 이동하는 주요 진입점
    
- 블로그로 이동하는 주요 진입점
    
- 소개 페이지 링크
    

선택적으로 최근 공개 콘텐츠를 표시할 수 있다. 다만 콘텐츠가 충분하지 않은 초기 단계에서는 빈 카드나 의미 없는 목록을 만들지 않는다.

홈 화면은 별도의 복잡한 대시보드가 아니라, 사이트의 콘텐츠를 발견하고 진입하는 출발점으로 설계한다.

---

## 7. 이야기·블로그·일반 페이지

### 7.1 이야기 목록

구성:

- 페이지 제목
    
- 이야기 목록
    
- 제목과 대표 이미지(있는 경우)
    
- 짧은 설명(있는 경우)
    

이야기 목록은 콘텐츠를 발견하기 쉬운 형태로 제공한다. 이미지가 없는 이야기에도 레이아웃이 자연스럽게 유지되어야 한다.

### 7.2 이야기 본문

구성:

- 제목
    
- 선택적인 대표 이미지
    
- 본문
    
- 필요할 경우 관련 이야기 링크
    

긴 이야기는 본문 너비와 문단 간격을 읽기 편하게 유지한다. 이미지가 콘텐츠에 중요한 경우 본문 흐름에 맞게 표시한다.

### 7.3 블로그 목록

구성:

- 제목
    
- 게시 날짜(데이터가 있는 경우)
    
- 작성자(데이터가 있는 경우)
    
- 짧은 설명 또는 도입부(있는 경우)
    

최신순 정렬을 기본으로 고려하되, 최종 정렬 규칙은 콘텐츠 데이터의 날짜와 공개 정책에 따른다.

### 7.4 블로그 본문

구성:

- 제목
    
- 게시 정보
    
- 본문
    
- 필요할 경우 관련 글 링크
    

본문은 경론 독서 화면과 일부 타이포그래피 규칙을 공유하되, 경론 트리나 각주 패널을 자동으로 표시하지 않는다. 해당 기능은 콘텐츠에 실제로 필요할 때만 제공한다.

### 7.5 일반 페이지

일반 페이지는 소개, 라이선스 등 사이트의 정적 안내 문서에 사용한다.

구성:

- 제목
    
- 본문
    
- 필요할 경우 본문 목차
    

일반 페이지는 별도의 복잡한 레이아웃을 만들지 않고 공통 문서 템플릿을 활용한다.

## 8. 모바일 및 반응형 설계

### 8.1 기본 원칙

모바일 화면은 데스크톱 레이아웃을 단순히 축소하지 않는다. GitHub 저장소의 모바일 탐색처럼 보조 탐색을 필요할 때 열 수 있도록 하고, 본문을 중심으로 화면을 구성한다.

### 8.2 공통 헤더

- 주요 메뉴는 공간에 맞춰 축약한다.
    
- 탐색 버튼으로 메뉴를 열고 닫을 수 있다.
    
- 메뉴 항목을 선택하면 일반적인 페이지 이동이 이루어진다.
    
- 메뉴가 열린 상태에서 화면 바깥을 누르거나 닫기 버튼을 누르면 닫힌다.
    
- 키보드 및 보조 기술로도 메뉴에 접근할 수 있어야 한다.
    

### 8.3 경론 읽기 화면

모바일에서는 본문을 기본 화면으로 제공한다.

- 왼쪽 트리는 탐색 버튼으로 여는 드로어로 제공한다.
    
- 오른쪽 목차·각주 패널은 도구모음에서 여는 보조 영역으로 제공한다.
    
- 좌측 트리와 오른쪽 패널을 동시에 열어 본문 공간을 과도하게 줄이지 않는다.
    
- 패널을 닫아도 읽던 위치를 유지한다.
    
- 긴 제목이나 서지 정보가 도구모음을 화면 밖으로 밀어내지 않도록 줄바꿈과 간격을 조정한다.
    

모바일에서의 권장 구조:

```
┌──────────────────────────┐
│ 보리도        메뉴        │
├──────────────────────────┤
│ 경로 표시                │
│                          │
│ 문서 제목                │
│ 서지 정보                │
│                          │
│ [자료 트리] [목차] [각주] │
├──────────────────────────┤
│                          │
│ 본문                     │
│                          │
│                          │
└──────────────────────────┘
```

실제 구현에서는 목차와 각주가 동일한 패널을 공유하므로, 도구모음의 각 버튼은 동일한 패널을 서로 다른 모드로 연다.

### 8.4 반응형 전환

정확한 픽셀 기준은 구현 시 확정하되, 전환 기준은 특정 기기의 이름보다 콘텐츠가 자연스럽게 표시되는지를 중심으로 정한다.

- 넓은 화면: 좌측 트리와 중앙 본문
    
- 중간 화면: 좁은 트리 또는 접을 수 있는 트리
    
- 작은 화면: 본문 중심, 트리와 보조 패널은 필요할 때 열기

## 9. URL과 페이지 이동

### 9.1 기본 원칙

모든 공개 문서는 고유하고 안정적인 URL을 가진다. 페이지 이동은 실제 링크를 기반으로 구현하며, 브라우저의 뒤로 가기·앞으로 가기·새로고침·직접 URL 접근이 정상적으로 작동해야 한다.

### 9.2 URL 구조 예시

```
/
 /texts/
 /texts/{section-slug}/
 /texts/{text-slug}/
 /texts/{text-slug}/{source-type}/{node-path}/
 /stories/
 /stories/{story-slug}/
 /blog/
 /blog/{post-slug}/
 /pages/{page-slug}/
```

위 경로는 개념 예시이며, 실제 규칙은 콘텐츠 데이터 및 파일 구조 명세서와 일치하도록 확정한다.

### 9.3 GitHub Pages 대응

- 사이트가 사용자 정의 도메인 또는 저장소 하위 경로에 배포되는 경우를 모두 고려한다.
    
- CSS, JavaScript, 이미지 등 정적 자산의 경로를 배포 환경에 맞게 생성한다.
    
- 콘텐츠 내부 링크는 최종 공개 URL로 정확하게 변환한다.
    
- 경로를 직접 입력해도 해당 정적 페이지에 접근할 수 있어야 한다.
    
- 공개 사이트에서 비공개 또는 미발행 콘텐츠의 경로와 메타데이터가 노출되지 않도록 한다.

## 10. 검색

검색은 전체 콘텐츠를 찾기 위한 보조 기능이다.

검색 대상은 공개된 경론, 이야기, 블로그, 일반 페이지로 한다. 검색 결과에는 콘텐츠 제목과 콘텐츠 유형을 기본으로 표시하고, 필요한 경우 짧은 설명을 제공한다.

정적 사이트이므로 검색 인덱스는 빌드 시 생성하는 방식을 우선 검토한다. 서버 기반 검색 서비스는 v1.0의 필수 요건이 아니다.

초기 구현에서는 검색 결과의 정확성과 간단한 운영을 우선하며, 고급 검색 문법이나 복잡한 필터는 추후 검토한다.

## 11. 예외 상태 및 오류 처리

모든 주요 화면은 정상 콘텐츠가 존재하는 상태 외에도 다음 상황을 처리해야 한다.

### 11.1 콘텐츠 상태

- 목록에 공개 콘텐츠가 없는 경우
    
- 문서에 목차가 없는 경우
    
- 문서에 각주가 없는 경우
    
- 대표 이미지가 없는 경우
    
- 선택적인 서지 정보가 없는 경우
    

데이터가 없다는 이유로 빈 프레임이나 불필요한 제목을 표시하지 않는다.

### 11.2 URL 및 링크 상태

- 존재하지 않는 URL은 404 페이지를 표시한다.
    
- 잘못된 내부 링크는 빌드 검증에서 탐지할 수 있어야 한다.
    
- 누락된 이미지가 콘텐츠 레이아웃을 무너뜨리지 않도록 한다.
    
- 미발행·비공개 콘텐츠는 공개 목록과 검색 결과에 포함하지 않는다.
    

### 11.3 접근성 및 상호작용

- 버튼과 링크를 구분한다.
    
- 메뉴, 드로어, 탭, 패널은 키보드로 사용할 수 있어야 한다.
    
- 현재 위치와 선택 상태를 시각적으로만 표현하지 않고 접근성 속성으로도 제공한다.
    
- 패널을 열 때 초점 이동과 닫을 때 초점 복귀를 적절히 처리한다.
    
- JavaScript가 작동하지 않는 경우에도 정적 본문과 기본 링크를 읽을 수 있도록 한다.

## 12. 정적 생성 및 구현 원칙

### 12.1 정적 페이지 생성

공개 사이트의 페이지는 로컬 콘텐츠를 바탕으로 빌드 시 생성한다. 페이지를 읽기 위해 별도의 백엔드 서버가 필요하지 않도록 한다.

### 12.2 콘텐츠와 UI 분리

- 콘텐츠 제목, 본문, 서지 정보, 트리 구조는 콘텐츠 데이터에서 가져온다.
    
- 공통 레이아웃과 디자인은 템플릿과 CSS에서 관리한다.
    
- 트리, 목차, 각주 패널은 생성된 HTML의 구조를 바탕으로 동작한다.
    
- 콘텐츠 파일에 디자인 관련 코드를 불필요하게 삽입하지 않는다.
    

### 12.3 Basecoat 자산 관리

배포 안정성을 위해 검토한 Basecoat CSS와 필요한 JavaScript를 프로젝트 내부에 포함하는 방식을 우선한다. CDN에 대한 상시 의존은 기본 배포 방식으로 삼지 않는다.

필요한 컴포넌트만 포함하고, 전체 JavaScript 번들을 무조건 사용하지 않는다. Basecoat의 공식 설치 문서와 컴포넌트 문서에 따라 필요한 스타일과 스크립트를 구성한다.

### 12.4 성능

- 필요하지 않은 JavaScript를 추가하지 않는다.
    
- 이미지 크기와 형식을 적절히 관리한다.
    
- 긴 문서에서도 트리와 패널의 상호작용이 본문 렌더링을 과도하게 방해하지 않아야 한다.
    
- 모든 문서 페이지가 공통 자산을 재사용하도록 한다.

## 13. 화면 검증 기준

v1.0 구현은 다음 기준을 만족해야 한다.

### 공통

- 주요 메뉴와 경로 표시가 올바르게 작동한다.
    
- 모든 공개 페이지가 고유 URL로 접근 가능하다.
    
- 브라우저 뒤로 가기와 새로고침이 정상 작동한다.
    
- 모바일 화면에서 콘텐츠가 가로로 불필요하게 넘치지 않는다.
    

### 경론 분류 및 목록

- 대분류 선택 시 올바른 목록으로 이동한다.
    
- 목록의 문헌 선택 시 해당 문헌으로 이동한다.
    
- 비공개 및 미발행 콘텐츠가 노출되지 않는다.
    

### 경론 읽기

- 왼쪽 트리는 현재 자료의 트리만 표시한다.
    
- 현재 문서가 트리에서 강조된다.
    
- 오른쪽 패널은 최초 진입 시 숨겨져 있다.
    
- 도구모음에서 목차를 열고 닫을 수 있다.
    
- 도구모음에서 각주를 열고 닫을 수 있다.
    
- 목차와 각주가 동일한 패널에서 전환된다.
    
- 각주 참조와 각주 내용 사이를 이동할 수 있다.
    
- 패널을 열고 닫아도 본문 위치가 불필요하게 초기화되지 않는다.
    
- 모바일에서 트리와 보조 패널이 별도로 열리고 닫힌다.
    

### 콘텐츠 유형별 화면

- 이야기, 블로그, 일반 페이지가 공통 디자인 원칙을 유지한다.
    
- 해당 유형에 필요하지 않은 경론 전용 UI는 표시하지 않는다.
    
- 이미지나 선택적 메타데이터가 없더라도 레이아웃이 유지된다.
    

### 접근성

- 키보드로 주요 메뉴와 패널을 조작할 수 있다.
    
- 선택 상태와 현재 위치를 인식할 수 있다.
    
- 링크와 버튼의 역할이 명확하다.

## 16. 최종 설계 요약

보리도 정적 사이트는 Basecoat UI의 기본 컴포넌트와 스타일을 활용하고, GitHub 저장소에서 익숙한 계층 탐색과 현재 위치 표시를 참조한다.

경론 읽기 화면은 왼쪽에 현재 자료의 트리, 중앙에 본문을 배치한다. 오른쪽 보조 패널은 기본적으로 숨기고, 본문 상단 도구모음에서 목차 또는 각주를 선택했을 때 열리는 하나의 패널로 구성한다. 모바일에서는 트리와 보조 패널을 필요할 때 열 수 있는 탐색 구조로 전환한다.

다른 콘텐츠 유형은 공통 레이아웃과 문서 스타일을 재사용하되, 경론 전용 기능을 불필요하게 노출하지 않는다. 모든 공개 콘텐츠는 안정적인 URL을 가진 정적 페이지로 생성한다.

**설계의 핵심은 GitHub의 탐색 명료성과 Basecoat의 일관된 UI 체계를 활용하면서, 보리도의 경론 읽기 경험을 중심으로 화면을 단순하게 유지하는 것이다.**
