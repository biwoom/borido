## 2. 확정과 검증의 구분

- **채택:** 명시 저장, 공개 조상 조건, 평평한 문서 URL, ID 링크/자산 참조, 하단 각주의 점진적 패널 표시, 최소 도구 구성, D23–D24의 한 체크아웃 `project/`·단일 `main`·Actions Pages 운영과 D26의 내부 세션 자동 브라우저 실행.
- **구현 전 계약 보완:** 실제 HTTP 엔드포인트/요청·응답, 코드 JSON Schema와 fixture, 실행 환경에 맞는 패치 버전·용량 제한 등. 이미 채택한 방향을 다시 미결정으로 돌리는 것이 아니다.
- **실측/환경 검증:** 실제 분류/서지·사용 자료, 본문/패널 치수·글꼴·전환점, 성능 예산, 배포 대상/설정. [R01–R06](decisions.md#remaining)에서 시점과 증거를 추적한다.
- **미실행:** W17 이후 공개 독서 화면 고도화·브라우저 콘텐츠 편집 UI·사이트 배포. 문서 통합 뒤 Git 전송과 W01–W16 콘텐츠/변환/정적 생성 Core 구현은 별도 요청으로 완료했다.

문서 개정 1.0, 향후 앱 버전, 데이터의 `schema_version`은 서로 다른 버전이다. 문서 파일명에는 버전을 붙이지 않고 이력·날짜를 안에 기록한다.

## 4. 아카이브와 검증 기록

[archive/README.md](archive/README.md)에 원래 이름→이동 경로→현재 담당 문서가 있다. [manifest.json](archive/manifest.json)에 아카이브 11개 원문의 이동 전 SHA-256·바이트 수를 기록했다. 기존 AGENTS는 `AGENTS-draft.md`로 보관해 과거 지침이 현재 루트 지침으로 오인되지 않게 했다.

아카이브 원문은 바이트 보존을 위해 내부 문구/링크를 수정하지 않는다. 과거 상대 링크는 당시 프로젝트 루트 기준이며, 현재 탐색에는 아카이브 인덱스를 사용한다. 문서 링크 검증의 기준은 현재 문서 세트와 아카이브 인덱스/manifest다.

이번 통합에서 확인할 항목은 원문 해시, 현재 링크/앵커·표, I/D/P/W/M 식별자, 작업 의존성, JSON 예시의 문법과 의미, 규칙의 문서 간 일치다. 제품 테스트·실제 분류 검증·브라우저/성능/배포 검증과 혼동하지 않는다.

### 4.1 2026-10-29 문서 검증 결과

- 아카이브 원문 11개의 SHA-256·바이트 수가 이동 전 기록과 일치한다.
- 현재 문서 10개(루트 2개·docs 7개·아카이브 인덱스 1개)의 로컬 링크/앵커 157개와 표·코드 블록을 확인했다. 아카이브 원문의 역사적 상대 링크는 바이트 보존 대상이며 이 수치에 포함하지 않았다.
- 최초 통합에서 D 22개·I 12개·R 6개·MVP M 17개·준비 P 3개·구현 W 35개를 확인했고 작업 의존 그래프에 순환이 없었다. 이후 D23–D26을 추가했으며 P/W/M 수는 바꾸지 않았다.
- JSON 예시 2개의 문법과 문서 ID/이력 대상·상태/본문 매핑의 일치를 확인했다. 아직 존재하지 않는 코드 JSON Schema로 전체 프로젝트 검증을 수행한 것은 아니다.
- 문서 통합 당시에는 제품 실행·패키지/스키마/브라우저 테스트·실제 분류/성능 검증·Git 초기화/전송·배포를 실행하지 않았다.

- W11은 Unicode/수동/중복 앵커, 목차, 반복 각주 왕복, 내부 참조와 원본 HTML·위험 링크·외부 이미지 차단을 구조화 결과와 진단으로 구현했다.
- W12는 실효 공개 레코드의 고유 URL, 접두사·도메인, 문서 ID/앵커 링크와 과거 경로의 현재 ID 직접 리디렉션을 구현했다.
- W13은 PNG/JPEG/WebP/GIF/PDF의 확장자·magic bytes·크기, 공개 상태와 참조 위치를 검증하고 공개 본문·대표·공통 자산만 UUID URL/복사 계획에 한 번 포함한다. 이 계획의 실제 파일 복사는 W15 전체 빌드에서 연결했다.

### 4.12 2026-10-30 W14–W16 검증 결과

- W14는 자동 이스케이프 템플릿으로 공개 콘텐츠 유형·분류·목록/빈 상태·홈과 검색 JSON·사이트맵·로컬 CSS를 생성한다. 템플릿은 프로젝트 원본을 직접 탐색하지 않는다.
