# 보리도 프로젝트 기획

- 통합 개정 1.0 · 2026-10-29 · 현재 개발 기준
- 채택 근거: [결정 기록](decisions.md). 구현 상태: W01–W04 기반/프로젝트 설정/로컬 API/최초 실행 UI 완료, W05 이후 미착수.

## 1. 프로젝트 정의

보리도는 개인이 불교 경론·이야기·블로그·일반 페이지를 자신의 컴퓨터에서 일반 파일로 작성·관리하고, 독립적인 정적 사이트 생성기로 웹사이트를 만드는 로컬 중심 콘텐츠 시스템이다.

편집 환경은 로컬 Node.js 서버와 브라우저 UI, 공개 환경은 HTML·CSS·JavaScript·필요한 자산만으로 이루어진다. 독자는 별도 애플리케이션 서버나 계정 없이 문헌을 탐색하고 읽는다. GitHub와 GitHub Pages는 관리/공개 수단이며 콘텐츠 원본의 형식이나 독서 화면을 종속시키지 않는다.

프로그램 저장소는 [biwoom/borido](https://github.com/biwoom/borido)다. 운영 콘텐츠와 배포 대상은 별도 사용자 프로젝트에서 지정한다. 상세 경계는 [실행 구조](technical-spec.md#architecture)를 따른다.

## 2. 철학과 우선순위

1. **원본 보존:** 콘텐츠는 사람이 이해할 수 있는 Markdown·JSON·미디어 파일로 남는다. 빌드·미리보기·업데이트가 원본을 바꾸지 않는다.
2. **사용자 통제:** 저장·공개·빌드·배포를 구분한다. 원본 변경과 원격 전송이 언제 일어나는지 사용자가 알 수 있어야 한다.
3. **안정적 식별:** ID·제목·파일 경로·공개 주소를 분리해 문헌의 편집과 구조 변경을 견딘다.
4. **명확한 공개 경계:** 비공개는 화면에서만 숨기는 상태가 아니다. 모든 생성 파일·참조·자산에서 제외하고 공개 Git 원본의 접근성은 별도로 다룬다.
5. **독서 우선:** 분류와 트리로 현재 위치를 이해하고 본문에 집중한다. 각주는 원문에 보존하고 정적 접근을 유지한다.
6. **작은 독립 시스템:** 별도 DB·범용 CMS·불필요한 프레임워크·외부 실행 API 의존을 추가하지 않는다. 실제 경론 한 편의 전체 흐름부터 검증한다.

## 3. 콘텐츠와 탐색

|유형|관리와 공개의 목적|
|---|---|
|경론|문헌 단위 서지와 신수대장경 분류, 번역·원문·연구의 독립 트리, 장문 독서|
|이야기|서사·출처·각색 정보와 선택적 이미지|
|블로그|게시일·작성자·태그·목록·본문|
|일반 페이지|소개·라이선스·안내, 명시적인 메뉴 표시|

미디어는 본문 콘텐츠 유형과 구분되는 자산이다. 경론 내부의 영역/구조/문서 레코드는 상위 콘텐츠 유형을 늘리는 기능이 아니다. 모델은 [콘텐츠 명세](content-spec.md#model)에서 정의한다.

신수대장경 분류→소속 경론→경론 개요→자료 영역→트리의 문서로 탐색한다. 번역·원문·연구는 깊이와 구성을 강제로 맞추지 않는다. 트리 깊이는 권/장/절 같은 고정 단계로 제한하지 않는다. 대응 자료는 명시적 연결만 사용한다.

## 4. 핵심 사용자 흐름

### 4.1 최초 실행과 운영

사용자는 프로그램과 별도의 프로젝트 경로를 지정해 실행한다. 마법사에서 새 프로젝트 생성/기존 열기를 구분하고 사이트 정보·공개 URL을 검증한다. GitHub 연결은 건너뛸 수 있다. 초기화 후 경론 목록으로 진입하며, 이후 설정에서 사이트·콘텐츠 편집 정책·시스템/인증 상태·백업/복구를 관리한다.

한 프로세스가 한 루트만 연다. 초기 버전은 외부 콘텐츠 경로·앱 내부 프로젝트 폴더 이동·최근 프로젝트 DB를 제공하지 않는다. 프로젝트 위치 변경은 종료→폴더 이동→새 경로로 재열기 절차로 지원한다.

### 4.2 작성에서 독서까지

경론/서지 작성→세 자료 영역 구성→구조/문서 작성→명시 저장→미저장/저장본 미리보기→공개 상태 지정→검증/빌드→공개 화면 확인→대상/결과 확인→사용자 승인 후 배포 순서다. 저장은 Git 커밋이나 배포를 자동 실행하지 않는다.

초기 저장은 버튼과 Cmd/Ctrl+S로 수행한다. 실패·충돌이 편집 텍스트를 버리거나 외부 변경을 덮어쓰지 않아야 한다. 파일 변경과 복구는 Git 미초기화 상태에서도 보호한다. 세부 UX는 [편집기](ui-spec.md#editor), 구현 경계는 [저장/복구](technical-spec.md#storage)를 따른다.

### 4.3 공개 사이트

홈·분류/목록·경론 개요/자료/본문·이야기·블로그·일반 페이지·검색·404/빈 상태를 제공한다. 페이지 이동은 실제 URL을 사용한다. JS가 없어도 본문·주요 링크·각주를 읽을 수 있으며, JS는 트리·패널·로컬 검색 등의 편의를 보완한다.

읽기의 필수 탐색은 자료 트리·목차·각주·자료 영역 이동·이전/다음이다. 인쇄 CSS를 제공하고 GitHub 원본/이력은 공개가 허용된 원본에 한해 연결한다. 다운로드·본문/링크 복사·글자 크기 조정은 후속 기능이다(D16).

## 5. 초기 범위와 후속 범위

초기에는 네 유형의 기본 편집과 공개, 분류/서지, 독립 트리, 미디어 기본 관리, 명시 저장·복구, 미리보기·검증·빌드, 검색/사이트맵, 반응형/키보드, Git/gh 상태·명시 배포를 구현한다. 사용 중인 미디어·참조·하위를 확인하지 않는 삭제나 자동 원본 수정은 허용하지 않는다.

자동 저장/미저장 입력의 주기적 복구, 고급 검색/필터·형태소 분석, 다중 스타일 팩·트리 리사이즈·현재 목차 강조, 복사/다운로드 등은 초기 흐름을 확인한 뒤 필요에 따라 추가한다. 문헌 분류/서지 전체를 먼저 수집하지 않고 실제 경론 한 편부터 검증한다.

계정/로그인·협업·원격 CMS·DB/캐시 서버·지식 그래프/온톨로지·AI 자동 분류·플러그인 마켓/범용 스키마 편집기·자동/예약 배포·저장소 생성 자동화·분석/추적·광고/추천은 초기 범위에서 제외한다.

아래는 과거 기획의 완료 기준을 보존·구체화한 목록이다. 작업별 검증은 [개발 계획](development-plan.md), 범위 변경은 [결정 기록](decisions.md#changes)으로 연결한다.

|---|---|---|
|M01 프로젝트 생성/열기|지정 경로에서 신규/기존 프로젝트와 공개 URL 설정을 안전하게 재현|W02–W04|
|M02 설정 분리|프로그램 저장소·사용자 원본·공개 URL·배포 대상을 혼동하지 않음|W02·W28–W30|

|M08 안전한 편집|브라우저에서 저장·충돌/실패 안내·변경 보존|W06·W23·W26|

|M11 원본 연결|공개 적합한 원본이 설정된 경우 GitHub 원본/이력 연결, 그 외에는 숨김|W18·W26·W29|

|M13 공개 통제|초안/비공개와 불필요한 자산이 모든 공개 파일에서 제외|W07·W13·W16·W24|
|M14 명시 배포|인증/권한/설정을 구분하고 검증·대상 확인·승인 후 지정 결과만 게시|W28–W31|

완료는 문서 존재나 화면 시안만으로 판정하지 않는다. 단위/통합/브라우저 검증과 실제 경론의 전체 흐름, 승인된 대상의 배포·복구 결과로 판단한다. 실행하지 않은 검증은 미실행으로 기록한다.
